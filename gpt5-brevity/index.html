Who Told GPT-5 to Be Brief?

Oct 24, 2026 · Leticia Lima

Six models played the same number-guessing task, and four of them found the answer, 42. Only GPT-5 scored well. In one sample its reasoning even credits "the instructions" for keeping it short, though the eval sent none. Two follow-up experiments show the lever is answer length, set by GPT-5's verbosity setting, not markdown.

Same answer, opposite scores

The task's scorer reads only the last word of the reply, and only if it is a plain number. Here is how one sample from each model ended.

What GPT-5 says it was told

Across 100 GPT-5 samples in five runs, the reasoning summaries refer to rules and machinery the eval never sent. These mentions are rare, and none uses the word "markdown". Only 2 samples credit instructions for keeping answers short. Tool-use rules come up more often: 6 samples across four runs.

The channels and the functions namespace match the system message OpenAI documents for its open-weight gpt-oss models: valid channels "analysis, commentary, final", with function calls routed to the commentary channel. OpenAI doesn't document GPT-5's version, but a third-party leak of its hidden API system prompt lists the same three channels. Simon Willison reported the leak in August 2025 and couldn't confirm it.

Experiment 1

Switching markdown back on changed nothing

OpenAI's reasoning guide says its reasoning models avoid markdown by default, and that "Formatting re-enabled" on the first line of the developer message turns it back on. I added that line as a system message (Inspect sends it as a developer message) and ran 20 samples next to a control.

GPT-5 saw the line: "The formatting is re-enabled, but I want to keep it minimal." It still answered in plain text. The lower score came from samples that stopped to ask questions; with 20 samples, that gap may be chance.

Experiment 2

Raising verbosity broke the score

GPT-5's API has a documented verbosity setting (low, medium, high; medium by default). I set it to high, kept everything else the same, and compared with three default runs.

The three default runs range from 0.79 to 0.99, so 0.19 is far outside run-to-run noise. Markdown barely appears even at high verbosity. The strict scorer rewarded GPT-5's terseness, and the terseness follows the verbosity setting.

Who said it was a single turn?

Two summaries say the conversation has one turn: "my interaction is limited to one turn" and "Since this is a single-turn scenario, I need to minimize verbosity". Nothing the eval sent says so. That belief comes from training or from OpenAI's hidden context; these logs can't tell which.

GPT-5 doesn't hold it consistently. Only 2 of 100 summaries mention it, and many samples ask the user for a range or offer to play again, which only makes sense if it expects another turn. It reads more like an occasional guess than a fact it was given.

What this does and doesn't prove

  • It shows GPT-5's summaries cite instructions, tools and channels that the eval never sent.
  • It doesn't show that GPT-5 is brief because it was told to be. Only 2 of 100 summaries say so; in the two October default runs, which scored 0.89 and 0.99, none do.
  • It shows the score depends on answer length, which the verbosity setting controls. The markdown opt-in had no visible effect.
  • It doesn't show how the verbosity setting reaches the model. "The instructions say to avoid unnecessary verbosity" suggests it arrives as an instruction, but OpenAI doesn't document that. The leaked hidden prompt points the same way: it includes a line setting a default "oververbosity" for the final answer. The leak is unconfirmed and from 2025, so it may not match today's model.
  • The summaries are written by OpenAI's summarizer, so their wording may not be the model's own.
  • Each run has 20 samples, and the gpt-5 alias may point to different snapshots over time.
  • The score gap is a scorer artifact. A prompt asking for a bare number brought Sonnet, Fable and Gemini to 0.98–0.99 with the same scorer.

Method notes

  • All runs used hawk local eval-set with provider API keys. For experiment 1, the system message appears in the logged conversation, and Inspect's OpenAI provider sends system messages as developer messages. For experiment 2, the logged request contains "text": {"verbosity": "high"}.
  • In a Hawk eval-set file, generation settings go under the model's args, as args: {config: {verbosity: high}}. A config key placed directly on the model entry is ignored without an error; my first high-verbosity attempt ran at default verbosity because of it, and became default run B.
